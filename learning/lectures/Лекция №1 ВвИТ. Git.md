## Notes in my words

Git нужен для отслеживания изменений в проекте и даёт возможность в любой момент вернуться к одной из прошлых версий проекта.

Репозиторий это хранилище, в котором Git сохраняет всю историю проекта

Коммиты желательно делать на каждое законченное действие, для того чтобы было возможно с меньшими затратами по времени отследить поломку в проекте

Команды для работы с Git:
`git init` - создаёт в текущем проекте папку .git , а значит появляется возможность коммитов и сохранения истории изменений проекта через Git
`git status` - показывает текущее состояние индекса (показывает какие файлы ещё не внесены в следующий коммит, какие файлы были изменены но не добавлены, а также файлы, которые входят в следующий коммит)
`git add (название файла)` - добавляет в следующий коммит файл, название которого было написано (с расширением файла, например txt)
`git add .` - добавляет в следующий коммит все изменённые файлы в проекте
`git commit -m "Пояснение к коммиту"`  - создание самого коммита, сохранение изменений в историю (команда дальше)
Команды для просмотра истории проекта (коммиты)
`git log` - полная запись каждого коммита
`git log --oneline` - по одной строке на каждый коммит(короткий хеш и пояснение к коммиту)
`git diff` - сравнивает каталог проекта с тем, что на данный момент внесено в индекс (будущий коммит)
`git diff --staged` - Сравнивает индекс с последним коммитом 

Ветки репозитория позволяют проводить эксперименты и отдельные задачи в ветках, отличных от основной (основная ветка - main)
Команды для работы с ветками:
`git branch` - показать список веток
`git branch (название ветки)` - создать ветку (название ветки), оставшись в текущей
`git switch (название ветки)` - перейти в ветку (название ветки)
`git switch -c (название ветки)` - создать ветку (название ветки) и сразу перейти в неё
## Key ideas

-Git - это система контроля версий, которая позволяет сохранять историю изменений проекта
-Основной цикл работы с Git состоит из трех шагов: изменение файлов -> добавление в индекс (`git add`) -> фиксация (`git commit`)
-Ветки позволяют вести отдельную разработку и экспериментировать, не изменяя основную версию проекта (main)
-Важно писать понятные сообщения к коммитам, чтобы в будущем легко находить нужные изменения.

## After: retrieval without notes

Git - это система контроля версий, которая сохраняет историю изменений в проекте. Она нужна, чтобы можно было вернуться к любой прошлой версии кода. Основной цикл работы состоит из трех шагов: изменение файлов, добавление их в индекс (`git add`) и фиксация (`git commit`). Ветки позволяют работать над разными задачами параллельно, не ломая основную версию проекта.

Пример: если я пишу программу и хочу добавить новую функцию, я создаю отдельную ветку, работаю в ней, а затем объединяю с основной версией, если всё работает.
